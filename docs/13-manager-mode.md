# 13. Manager mode

Manager mode는 manager가 **worker와 같은 화면 위에서** 앱 데이터를 고치는 층입니다. 모드를 끄면 권한과 상관없이 모두 같은 화면이고, 켜면 고칠 수 있는 요소마다 테두리가 생기고 누르면 그 요소의 관리 패널이 열립니다. 역할 정의는 [07](07-security.md), 시각 토큰은 [09](09-design-system.md)가 소유합니다. 지금은 템플릿 편집 화면에만 있습니다.

> 이 문서의 표기 — ✅ 사용자가 정한 것 · 📏 지금 코드가 하는 것(사실) · ❓ 아직 정하지 않은 것. ❓는 정해지면 ✅로 옮기고 질문을 지웁니다.

## 1. 정한 것

- ✅ 이름은 「Manager mode」입니다. 클라이언트가 바로 알아듣는 이름을 고릅니다(Master·Manage·Edit 기각, 2026-10-13).
- ✅ **원본 UI를 구조적으로 건드릴 수 없습니다.** 조심해서 안 건드리는 것이 아니라, 원본 컴포넌트가 모드의 존재를 모르게 만듭니다(2026-10-13).
- ✅ 컨트롤러마다 자기 관리 폼이 있고, 모드가 켜지기를 기다렸다가 자기 폼을 보여 주고 CMS를 고칩니다(2026-10-13).
- ✅ 요소는 최대한 작게 잡습니다. 텍스트 패널 전체가 아니라 텍스트 칸 하나하나가 요소입니다. 템플릿 화면의 모든 요소 중 고칠 수 있는 것만 잡습니다(2026-10-13).
- ✅ 테두리는 아주 두껍고, 흰 바탕에 움직이는 그라디언트입니다. 마우스를 올리면 빛이 세집니다. 누르면 캔버스 쪽으로 패널이 자라고, 패널 높이는 내용이 정합니다. 테두리와 패널은 한 path로 이어진 둥근 모양입니다(2026-10-13).
- ✅ 오른쪽 레일의 요소는 패널이 왼쪽으로, 왼쪽 레일의 요소는 오른쪽으로 열립니다(2026-10-13).
- ✅ 테두리뿐 아니라 요소 안쪽을 눌러도 열립니다. 모드 중에는 원본이 조작되지 않습니다(2026-10-14).
- ✅ 여러 템플릿이 같이 쓰는 파운데이션은 각자의 페이지에서 관리합니다. Manager mode에는 링크만 둡니다(2026-10-13).
  - 파운데이션은 컬러·판형 종류·RGB/CMYK 같은 것입니다.
  - 관리하는 곳은 별도의 **파운데이션 모달**이고, 여러 경로에서 여는 공용 페이지입니다. 링크는 이 모달의 해당 섹션으로 엽니다(2026-10-14).
- ✅ **캔버스는 Manager mode 대상이 아닙니다.** 캔버스에서는 제어할 것이 없습니다(2026-10-14).
- ✅ **저장은 Manager mode를 끌 때 한 번에 고릅니다.** 모드 중 고친 값은 바로 저장하지 않고 모아 두었다가, 모드를 끌 때 저장할지 버릴지 고릅니다(2026-10-14).
  - 이 결정은 2026-10-13의 「저장은 바로 반영한다」를 바꾼 것입니다.
  - CMS의 초안·게시 UX는 여전히 가져오지 않습니다.
- ✅ **속도가 핵심입니다.** 사용자가 예측하지 못한 새 층이라 느리면 UX가 무너집니다(2026-10-14). 기준치는 6절에 있습니다.

## 2. 구조

📏 세 층으로 나뉘고, 원본 쪽에는 속성 한 줄만 들어갑니다.

| 층 | 자리 | 책임 |
| --- | --- | --- |
| 원본 표시 | 각 원본 컴포넌트 | 요소에 `data-manager-target="<종류>:<열쇠>"`와 `data-manager-label`을 **항상** 답니다. 모드 분기·래퍼는 넣지 않습니다. 모드 중에도 평소 동작을 할 버튼에는 `data-manager-passthrough`를 답니다 |
| 층 | `src/components/studio/shared/manager-overlay.tsx` | body 포털. 표시된 요소를 찾아 테두리·누름 판·패널을 그립니다. 모양은 `manager-shape.ts` |
| 모드 상태 | `src/components/studio/shared/use-manager-mode.ts` | 주소가 갖습니다. `?manager`는 켜짐, `?manager=<종류>:<열쇠>`는 그 요소를 고른 상태 |
| 등록표 | `src/components/studio/template/template-manager-overlay.tsx` | 종류 → `{ title, render, accepts }`. 한 종류를 여러 폼이 나눠 쓰면 열쇠로 고릅니다 |
| 폼 | `src/components/studio/template/manager-forms/` | 요소별 관리 폼 |
| 데이터 | `src/features/template-customization/services/template-records.client.ts` | 초안 캐시 `readTemplateDraft`·쓰기 `patchTemplate`. 모드가 켜진 템플릿(`setManagerDraft`)의 쓰기는 Payload 초안으로만 쌓입니다. 끌 때 `publishTemplateDraft`(저장)·`discardTemplateDraft`(버리기) |
| 끄기 | `src/components/studio/template/template-manager-rail.tsx` | 고친 값이 있으면 저장·버리기·계속 고치기를 묻습니다 |
| 미리보기 | `src/app/(frontend)/studio/template/[templateSlug]/page.tsx` | `?manager`이고 manager 이상이면 게시본 대신 최신 초안으로 화면을 그립니다 |

새 요소를 붙이는 순서:

1. 원본 요소에 `data-manager-target`·`data-manager-label`을 답니다.
2. `manager-forms/`에 폼을 만듭니다. 4절 규칙을 따릅니다.
3. 등록표에 한 줄을 넣습니다.
4. 6절의 불변식 테스트와 속도를 확인합니다.

## 3. 층 동작

| 항목 | 📏 지금 |
| --- | --- |
| 켜기 | 오른쪽 레일 맨 아래 「Manager mode」 버튼(manager 이상). 켜는 순간 템플릿 초안을 미리 받아 둡니다. 지난번에 저장하지 않은 고친 값이 있으면 그 값으로 화면을 다시 그립니다 |
| 끄기 | 같은 버튼. 고친 값이 있으면 「저장 / 버리기 / 계속 고치기」 창이 뜹니다. 저장하면 게시되고, 버리면 마지막으로 게시한 상태로 돌아갑니다 |
| 요소 찾기 | 매 프레임 `[data-manager-target]`을 찾습니다. 등록되지 않았거나, 크기가 0이거나, 다른 것에 가려진 요소는 그리지 않습니다 |
| 테두리 | 6px. 상태는 기본·hover·선택 셋. 동작 줄이기 설정이면 그라디언트가 돌지 않습니다 |
| 열기 | 테두리나 요소 안쪽을 누르면 열립니다. 한 번에 하나만 열립니다. 요소 안에 `data-manager-passthrough` 버튼이 있으면 그 버튼도 눌러 평소 동작을 합니다(Layers 묶음 줄) |
| 방향 | 요소 중심이 화면 가운데보다 오른쪽이면 왼쪽으로, 아니면 오른쪽으로 자랍니다. 위쪽은 요소 윗변에 맞춥니다 |
| 크기 | 폭 320px 고정. 높이는 내용, 화면을 넘으면 패널 안에서 스크롤합니다 |
| 패널 머리 | `<요소 라벨> · <폼 제목>`과 닫기(X) 버튼 |
| 닫기 | X 버튼, Esc(패널 안에 포커스가 있을 때), 같은 요소 다시 누르기. 다른 요소를 누르면 그쪽으로 옮겨 갑니다. 닫을 때 입력 중인 칸의 값도 씁니다 |
| 키보드 | 요소마다 테두리 위에 보이지 않는 버튼이 있고 포커스를 받으면 보입니다. 패널은 dialog가 아니고 포커스를 옮기지 않습니다 |

같은 레일의 「Manager mode (CMS Style)」는 이 층이 아니라 템플릿 목록·생성·수정·휴지통 모달입니다(`shared/data-editor.tsx`). 「QA mode」는 자리만 있습니다.

## 4. 패널 규칙

### 정한 것

- ✅ 패널은 그 요소 하나의 데이터만 고칩니다.
- ✅ 패널에는 「저장」 버튼이 없습니다. 고친 값은 모드를 끌 때 저장합니다(1절).
- ✅ 파운데이션 값은 패널에서 고치지 않고 **파운데이션 모달**로 보냅니다. 이 모달은 「Manager mode (CMS Style)」 템플릿 목록 모달과 별개의 새 모달입니다(2026-10-14).
- ✅ **컬러 패널**은 여러 레이어에 공통으로 나오는 패널입니다. 색 자체를 고치려면(어떤 토큰의 색을 바꾸는 등) 파운데이션 모달을 열고 컬러 섹션으로 이동합니다(2026-10-14).
- ✅ **레이어 패널(Layers)의 텍스트 묶음**(2026-10-14)
  - 모드 중 Layers의 Text 줄을 누르면 평소처럼 텍스트가 골라지고(오른쪽 패널이 텍스트 칸들로 바뀜), 그 묶음의 관리 패널이 열립니다.
  - 묶음 패널에서는 레이어마다 보일지 여부, 편집 가능·값 고정, **순서**만 고칩니다.
  - 레이어 이름과 그 밖의 텍스트 설정은 오른쪽 패널의 그 요소(텍스트 칸)에서만 고칩니다.
  - 📏 Layers에는 텍스트 레이어 하나하나의 줄이 없고 Text·Symbol·Background 묶음 줄만 있습니다. 텍스트 칸 하나의 「칸 설정」은 오른쪽 그 칸을 눌러 엽니다.

### 기본값

사용자가 따로 정하지 않아서 아래처럼 만듭니다. 바꾸려면 말하면 됩니다.

- 고른 값은 고르는 즉시, 적는 값은 칸을 벗어날 때 초안에 쌓입니다. 판형처럼 종류와 크기가 같이 맞아야 하는 폼은 폼 밖으로 나갈 때 한 번에 쌓습니다.
- 고친 값은 모드 중 내 화면(캔버스·원본 패널)에 바로 보입니다. 다른 사용자에게는 저장해야 보입니다.
- 저장하지 않고 페이지를 떠나면 고친 값은 초안으로 남고, 다음에 모드를 켜면 이어서 보입니다. 모드가 꺼진 화면은 늘 게시본입니다.
- 「썸네일 만들기」·「기본 화면 지우기」도 다른 값처럼 초안에 쌓이고 끌 때 저장됩니다.
- Layers의 Vector·Image 묶음도 텍스트 묶음과 같은 규칙입니다. 레이어 이름은 CI 색 줄·이미지 칸 패널 맨 위에서 고칩니다. 오른쪽 패널에 요소가 없는 Vector 레이어는 지금 이름을 고칠 자리가 없습니다.
- 컬러 패널은 파운데이션 모달 컬러 섹션을 여는 링크만 둡니다.
- 불러오는 중·실패·빈 목록은 모든 패널이 같은 표시를 씁니다. 실패는 화면 읽기 프로그램에도 알립니다.
- 잘못된 값은 그 칸 바로 아래에 오류 문구를 띄웁니다.
- 컨트롤에는 늘 화면에 보이는 이름표를 붙입니다.
- Esc를 누르면 열린 패널이 닫힙니다.
- 패널 안 목록은 따로 스크롤하지 않습니다. 패널 스크롤 하나만 둡니다.
- 같은 뜻의 토글은 「허용/숨김」으로 맞춥니다. 끄면 그 줄이 worker 화면에서 사라지기 때문입니다.

### ❓ 아직 정하지 않은 것

- 파운데이션 모달에 컬러·판형 종류·RGB/CMYK 말고 무엇이 들어가나? 지금 패널이 Payload로 보내는 것은 이미지·그래픽 프로파일, 카테고리, 샘플 이미지, 로고, 템플릿 버전 기록입니다.
- 파운데이션 모달은 어디어디에서 여나?
- 캔버스를 빼면 「Figma에서 다시 가져오기」 버튼은 어디로 가나? 폼(`TemplateCanvasManagerForm`)은 남아 있지만 지금 여는 자리가 없습니다.
- 열린 패널이 다른 요소를 덮으면? 지금은 덮인 요소의 테두리가 사라지고 눌리지 않습니다.
- 작은 요소가 몰린 곳(선택 카드 안의 썸네일·이름·카테고리·기본값 아이콘)의 빽빽한 테두리를 어떻게 하나? 겉모습이라 팀원 몫일 수 있습니다.

겉모습(색·간격·문구 톤)은 이 문서가 정하지 않습니다.

## 6. 검증

- **원본 불변**: `template-workspace.test.tsx`의 「Manager mode는 원본 화면을 바꾸지 않는다」가 켬·끔의 원본 DOM이 같은지 봅니다. 새 요소를 붙이면 이 테스트가 그 요소를 덮는지 확인합니다.
- **초안**: 모드 중 고친 값이 게시본(`/api/templates/<id>`)은 그대로이고 초안(`?draft=true`)에만 있는지, 끄면서 저장·버리기 뒤 둘이 같아지는지 봅니다. `template-records.client.test.ts`가 쓰기 경로를 잡습니다.
- **속도**: 아래 세 동작을 `performance.now()`로 잽니다(로컬 dev, 2026-10-14 기준).
  - 레일 버튼 → 테두리: 0.04초
  - 요소 → 패널·입력칸: 0.03~0.06초
  - 토글 → 표시: 즉시
- **속도 규칙**:
  - 모드 상태는 `window.history.replaceState`로 바꿉니다. `router.replace`는 서버 페이지를 통째로 다시 받아 옵니다.
  - 표시용 읽기는 받아 둔 초안을 씁니다. 저장 직전 읽기만 새로 받습니다.
